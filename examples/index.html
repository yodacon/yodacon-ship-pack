Yodacon Ship Pack · Tutorial Note 1 · October 2026

From Sprite Sheet to Moving Ship: Starting a Game With the Yodacon Ship Pack

Yodacon Ship Pack project, yodacon.org/ship-pack

Abstract—The Yodacon Ship Pack publishes the starships of the 1997–1998 ConEx Escape Velocity plugins as GPL-licensed PNG sprite sheets with a JSON description of each ship. This note shows a newcomer how to start a project with them: where the files are, the one convention that governs every sprite, the three functions that turn a heading into pixels on screen, and how to carry those three functions into an engine of their own. Every listing is taken from, and cites, the pack's own code.

Index Terms—sprite sheets, 2-D rendering, game loops, pixel art, asset pipelines.

I. Introduction

A ship in a 1990s top-down space game is not rotated at run time. It is drawn 36 times in advance, once per 10° of heading, and the game shows whichever drawing is closest to the way the ship points. The pack keeps that design [1]. Rendering a ship is therefore not image rotation but frame selection: compute one integer from the heading, find that frame's rectangle in a sheet, and copy the rectangle to the screen. The rest of this note builds those steps (Section III), puts them in a game loop (Section IV), moves them to other engines (Section V), and adds your own content (Section VI).

II. What Is in the Pack

Each ship lives in a folder <edition>/ships/<slug>/, where the edition is conex (1997), override (1998) or konex. Table I lists the files. catalog.json at the root lists every edition and ship, and is the only file a program needs to discover the rest [2].

The part of ship.json a renderer needs is the sprite object (Listing 1). Frame sizes differ between ships (36 to 120 pixels), so never hard-code them; read them here.

III. The Core: Heading to Pixels

A. The Convention

Heading θ is measured in degrees clockwise from straight up, which matches screen coordinates whose y axis points down. Frame 00 is nose-up and each following frame is 10° further clockwise [3, lines 12–17]. The frame to show and its place in the sheet follow directly:

f = ⌊θ / 10⌋ mod 36(1)

x = (f mod 6) · w,   y = ⌊f / 6⌋ · h(2)

where w and h are frame_width and frame_height. The modulo in (1) must wrap negative headings too, which JavaScript's % does not; Listing 2 corrects for it.

B. Loading

A ship is its ship.json plus one decoded image. loadShip() fetches both (Listing 3) and caches the image, so ten ships of one kind cost one download [3, line 56].

C. Drawing

Drawing copies the rectangle from (2) to a point centred on the ship (Listing 4). Two details matter for 1997 pixel art: turn off image smoothing, and round the destination to whole pixels; scale only by whole numbers, or the pixels smear.

IV. A First Game Loop

With Listings 2–4, a flyable ship is a page and some 40 lines. Create index.html beside a copy of the pack (or import the library from yodacon.org or jsDelivr [3, lines 6–8]) and serve the folder with any static server, for example python3 -m http.server; ES modules do not load from file://. Listing 5 is the loop of the Canvas example [4]: turn with the arrow keys, thrust along the frame shown so motion matches the picture, integrate by the frame time, and draw.

The unit vector for heading θ under this convention is (sin θ, −cos θ). The demo and the flying games in projects/ (Orbital Defence, Slingshot, ConEx Courier) use it, so they are worked examples of the same loop.

C. Any Other Engine

In three.js, pygame, raylib, SDL, Unity or Bevy the pattern is the same: load sheet-alpha.png, compute the source rectangle with (2), and draw it. In UV terms the rectangle is u = (f mod 6)/6, v = ⌊f/6⌋/6 with size 1/6 × 1/6, flipping v in engines whose texture origin is the bottom left [6]. If an engine cannot take a sheet, use the single files frames/NN.png and index them by f.

VI. Building On It

A. Finding Ships

Read catalog.json instead of hard-coding slugs, so new ships appear in your game when the pack grows. loadCatalog() [3, line 77] returns every edition with every ship's file URLs.

B. Using the 1997 Numbers

ship.json keeps each ship's original Escape Velocity statistics under stats: Speed, Accel, Maneuver, Shield, Armor, Holds and more. Scale them into your units rather than inventing new ones; Fleet Tactics and ConEx Courier in projects/ show two such mappings in their READMEs.

C. Licence and Credit

The art is GPL-2.0-or-later. Keep the credit line (CREDIT in the library) in your game, and if you ship it, add it to the pack's leaderboard through USED-IN.md [7].

VII. Conclusion

Rendering a pre-rotated sprite comes down to Equation (1), Equation (2) and one copy of a rectangle. Those three steps are about a dozen lines in the pack's library and carry unchanged into any engine. Start from Listing 5, swap in your engine's draw call, and the 1997 fleet is flying in your project.
