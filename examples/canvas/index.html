A Game Loop on Canvas 2D: How the Canvas Example Uses the Pack

Yodacon Ship Pack project, yodacon.org/ship-pack

Abstract—The Canvas example flies a pack ship with the library's loadShip() and drawShip(), handling taken from the ship's 1997 statistics and a fixed-timestep loop. This note follows the page's source and the library code it calls.

Index Terms—Canvas 2D, sprite sheets, fixed timestep, pixel art.

I. Introduction

The Canvas example is a flyable ship in under 60 lines of script. It uses two functions from the pack's library, loadShip() and drawShip() [1], and a fixed-timestep loop. This note follows the page's source, examples/canvas/index.html, from loading to the drawn frame.

III. Loading

loadShip(edition, slug) fetches ship.json, then loads and decodes the sheet (Listing 1). It resolves only when the image is ready, so the first frame never draws an empty sprite. The query string picks the ship, so ?edition=override&ship=callisto needs no code change.

IV. Handling From the 1997 Record

The ship's original Escape Velocity numbers live in ship.meta.stats. The page maps three of them to its own units (Listing 2): Speed caps velocity, Accel is thrust and Maneuver is turn rate, so a Dart and a Large Pin fly differently with no per-ship code.

V. Update: Thrust Along the Frame Shown

Heading is continuous, but the picture changes only every 10°. The page thrusts along the heading of the frame on screen, a = ⌊θ/10⌋·10°, so the ship always moves the way it appears to point (Listing 3). With screen y pointing down, the unit vector is

d(a) = (sin a, −cos a)(1)

VI. Draw: One Library Call

drawShip(ctx, ship, heading, x, y, scale) (index.html:73) selects the frame with f = ⌊θ/10⌋ mod 36, finds its cell, and copies it centred on (x, y) with smoothing off and rounded coordinates (Listing 4). The canvas itself is scaled by CSS to fit the page, so the page also sets image-rendering: pixelated on it (index.html:14).

VII. The Loop

Physics advances in fixed 1/60 s steps while drawing happens once per animation frame (Listing 5). The accumulator is capped at 0.25 s so a background tab does not return to a burst of catch-up steps.

VIII. Using It in Your Project

  1. Import loadShip and drawShip from your copy of the library or a pinned CDN URL (index.html:30).
  2. Await one loadShip() per ship type; reuse the result for every ship of that type.
  3. Keep each ship's x, y and heading; call drawShip() per ship per frame.

The flying games in projects/ (Orbital Defence, Slingshot, ConEx Courier) are this loop grown into games [2].

IX. Conclusion

Two library calls carry the whole asset path from URL to pixels; everything else on the page is ordinary game code, which is the point: the pack stays out of your game's way.
