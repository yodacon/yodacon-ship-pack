Ships as HTML: How the <yodacon-ship> Example Uses the Pack

Yodacon Ship Pack project, yodacon.org/ship-pack

Abstract—The web-component example builds a playground and a full fleet from catalog.json using the library's <yodacon-ship> element. This note traces the page's source, then the element's own loading, rendering and spin logic in the library.

Index Terms—Web components, custom elements, shadow DOM, CSS sprites.

I. Introduction

Importing the pack's library registers a custom element, <yodacon-ship>, that shows any ship at any heading from HTML alone. This page demonstrates it twice: a live element driven by a form, and every ship in the catalogue spinning. This note covers how the page uses the element, then how the element uses the assets inside the library [1].

II. One Script Tag

The page loads the library as a module (index.html:35). From then on, markup such as index.html:44 is a ship. The element shows its light-DOM children until the ship loads, so a plain <img> of frame 00 inside it is a good fallback.

IV. Building From the Catalogue

The page never lists ships itself. It walks catalog.json and creates one spinning element per ship (Listing 1), so ships added to the pack appear here with no edit. Scale is chosen per ship to keep whole numbers: 1 for frames wider than 64 pixels, else 2.

V. Attributes Are the Interface

The form writes attributes; the element observes them and re-renders (Listing 2). Changing ship or edition reloads, while heading, scale and spin only redraw (lib/yodacon-ship-pack.js:240).

VI. Inside the Element

The element's shadow root holds one <div> painted with the sheet, the DOM technique of Tutorial Note 2 [2] packaged as a component. Loading fetches only ship.json in script; the sheet is left to the browser as a CSS background (Listing 3). A load counter discards answers to superseded requests when attributes change quickly.

Rendering sizes the box to one frame times the scale and positions the scaled sheet (Listing 4), with the rectangle from frameRect():

(x, y) = ((f mod 6) · w, ⌊f / 6⌋ · h)(1)

VII. Spinning Responsibly

A spin element advances one frame at about 12 fps, a full turn in three seconds. Two checks keep a page of spinning ships cheap and polite: an IntersectionObserver pauses elements that are off screen (lib/yodacon-ship-pack.js:227), and prefers-reduced-motion stops spinning altogether (lib/yodacon-ship-pack.js:298).

VIII. Using It in Your Project

  1. Add one module script tag pointing at the library.
  2. Write <yodacon-ship ship="dart" edition="conex" heading="90" scale="2">.
  3. Set heading (attribute or property) from your code; listen for load and error events if you need them.

The pack page itself uses the element for every ship card, which is the best demonstration of it at scale.

IX. Conclusion

The element turns the pack into HTML vocabulary: a catalogue read once, one JSON file per ship and one CSS background, with the frame arithmetic hidden behind a heading attribute.
